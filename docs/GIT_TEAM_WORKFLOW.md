# 🚀 Командная разработка в Varwin 18 через Git и GitHub

> **Решение главной боли командной разработки в Varwin:**  
> Вместо передачи многогигабайтных архивов `.vwp` (2–3 ГБ) при каждом изменении кода или сцены — полноценный контроль версий в **Git/GitHub**: размер репозитория всего **~60 КБ** (в 30 000 раз легче!), мгновенный `push`/`pull` за 1 секунду, ветки, Pull Requests и наглядные diff'ы.

---

## 🎯 Почему `.vwp` такой тяжелый и как устроен `varwin-git`

### Проблема классического экспорта `.vwp`:
Когда вы экспортируете проект через Varwin UI в `.vwp`, Varwin заново компилирует и упаковывает **все 3D-ассетбандлы Unity** для трёх платформ сразу (Windows, Linux, Android/Oculus). В итоге даже для пустой комнаты проект весит **1.5 – 2.5 ГБ**. Передавать такой файл коллегам или заливать в файлообменники долго и неудобно, а версионирование и слияние изменений (merge) невозможны.

### Решение `varwin-git`:
У всех разработчиков в команде стандартные библиотеки объектов (кнопки, свет, персонажи, тексты, спавны) и окружения уже установлены в Varwin.  
Утилита **`varwin-git`** декомпозирует проект в **чистые структурированные текстовые исходники**:

```
MyVarwinProject/
├── project.json              # Настройки проекта, название, GUID, флаги Mobile/Multiplayer (~200 байт)
├── .gitignore                # Игнорирование временных кэшей и логов
├── README.md                 # Документация проекта команды
└── scenes/
    └── Main Scene/
        ├── scene.json        # GUID шаблона окружения, точка спавна камеры/игрока (~500 байт)
        ├── objects.json      # Дерево 3D-объектов, координаты x/y/z, повороты, свойства инспектора (~30 КБ)
        ├── code/
        │   └── Main.py       # Чистый Python-код сцены (редактируется в VS Code, Cursor, PyCharm)
        └── logic/
            ├── Blockly.xml   # Визуальные блоки Blockly в XML (читается и диффится)
            ├── Blockly.py    # Сгенерированный код логики блоков
            └── blockly_meta.json
```

**Итоговый вес проекта в Git:** **~60–75 КИЛОБАЙТ**!

## 🛠️ Установка и быстрый старт

Утилита входит в состав репозитория [VarWin-mcp](https://github.com/B10Sreg/VarWin-mcp):
- **Linux:** `./bin/varwin-git` или `python3 scripts/varwin_git.py`
- **Windows:** `bin\varwin-git.cmd` или `python scripts\varwin_git.py`

## 📖 Пошаговый сценарий командной работы

### 1. Первый экспорт проекта и публикация на GitHub

Создайте проект в Varwin или выберите существующий. Экспортируйте его одной командой:

```bash
# Посмотреть список всех проектов в локальном Varwin
./bin/varwin-git list

# Экспортировать проект в новую папку репозитория
./bin/varwin-git export "Color Spheres & Text" --dir ./my-game-repo
```

Создайте пустой репозиторий на **GitHub** (например, `https://github.com/YourTeam/my-game-repo.git`) и опубликуйте проект:

```bash
cd my-game-repo
git remote add origin https://github.com/YourTeam/my-game-repo.git
git branch -M main
git push -u origin main
```

Всё! Проект сохранён на GitHub, весит несколько килобайт, и любой участник команды может подключиться к работе.

---

### 2. Клонирование проекта другим разработчиком команды

Новый участник команды на своём компьютере (Linux или Windows) выполняет:

```bash
# 1. Клонируем проект с GitHub
git clone https://github.com/YourTeam/my-game-repo.git
cd my-game-repo

# 2. Применяем проект в локальный Varwin
varwin-git apply
```

✨ **Готово!** Проект мгновенно появляется в списке проектов локального Varwin.  
Все сцены, 3D-объекты с их точными координатами, блоки Blockly и скрипты Python восстановлены со 100% точностью.

---

### 3. Совместная разработка, ветки и Pull Requests

Вместо хаоса версий вы используете стандартный профессиональный Git-воркфлоу:

1. **Создайте ветку для фичи:**
   ```bash
   git checkout -b feature/shooting-mechanic
   ```
2. **Внесите изменения:**  
   - Вы можете расставить объекты прямо в 3D-редакторе Varwin или изменить логику в Blockly.
   - Либо вы можете напрямую открыть `scenes/Main Scene/code/Main.py` в **VS Code / Cursor / PyCharm** и писать Python код с полной подсветкой синтаксиса и автодополнением!
3. **Сохраните изменения в репозиторий:**
   ```bash
   varwin-git push -m "Добавлена стрельба и обработка попадания"
   ```
   *(Команда `push` автоматически выгружает актуальное состояние из Varwin, создаёт Git-коммит и отправляет ветку на GitHub).*
4. **Создайте Pull Request на GitHub:**
   - На GitHub в Pull Request будет наглядно видно построчный diff:
     - Какие строки Python кода изменились,
     - Какие объекты переместились (изменение координат в `objects.json`),
     - Какие блоки добавились.
   - Коллеги проводят Code Review и мерджат ветку в `main`.

---

### 4. Получение обновлений от коллег

Когда в ветку `main` влиты изменения от других участников команды, просто выполните:

```bash
varwin-git pull
```

Утилита выполнит `git pull` с GitHub и сразу накатит обновлённую конфигурацию и код в ваш локальный Varwin.

## 📋 Справочник команд `varwin-git`

| Команда | Описание | Пример |
|---|---|---|
| `varwin-git list` | Показать список всех локальных проектов с ID и датами обновления | `varwin-git list` |
| `varwin-git export <ID/Name>` | Экспорт проекта из Varwin в Git-структуру файлов | `varwin-git export 1 --dir ./my-repo` |
| `varwin-git apply` | Загрузить / обновить проект в локальный Varwin из папки Git | `varwin-git apply --dir ./my-repo` |
| `varwin-git status [path]` | Сравнить Git-репозиторий с состоянием в базе Varwin (код, блоки, объекты) | `varwin-git status` |
| `varwin-git diff [path]` | Построчный цветной diff изменений кода Python и логики Blockly | `varwin-git diff` |
| `varwin-git clone <URL>` | Клонировать удаленный Git-репозиторий и сразу применить его в Varwin | `varwin-git clone https://github.com/org/repo.git` |
| `varwin-git push -m "..."` | Выгрузить из Varwin, закоммитить и запушить на GitHub | `varwin-git push -m "Update logic"` |
| `varwin-git pull` | Подтянуть изменения с GitHub и накатить в локальный Varwin | `varwin-git pull` |

## 🤖 Интеграция с AI через MCP Server

Если вы используете **Claude Desktop**, **Cursor**, **Antigravity** или **Cline**, MCP-сервер предоставляет встроенные инструменты:
- `varwin_git_status` — AI-ассистент проверяет различия между рабочим деревом Git и живым проектом Varwin.
- `varwin_git_export` — AI-ассистент может сам подготовить и выгрузить проект в репозиторий по голосовой или текстовой просьбе.
- `varwin_git_apply` — AI-ассистент может накатить проект из любого репозитория прямо в ваш рантайм Varwin.

## ❓ Часто задаваемые вопросы (FAQ)

### 1. Будет ли работать на Windows 10/11?
**Да, абсолютно.** Скрипт автоматически находит базу данных Varwin как на Linux (`~/.config/VarwinData18/`), так и на Windows (`%APPDATA%\VarwinData18\`). Для Windows предусмотрен батник `bin\varwin-git.cmd`.

### 2. Что если проект использует кастомные 3D-модели (FBX/GLTF) или звуки?
Если у вас есть кастомные файлы ресурсов, положите их в подпапку `resources/` внутри репозитория. Если файлы весят больше 50 МБ, включите стандартный `git lfs track "*.fbx"`.

### 3. Можно ли мерджить ветки, если два человека меняли код?
**Да!** Поскольку код хранится в обычном `Main.py`, Git выполняет слияние (merge) так же легко, как и в любом обычном Python или веб-проекте. Конфликты разрешаются стандартными средствами Git.
